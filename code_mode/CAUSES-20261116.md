# CATIA 零件修改 PTC 测试：独立原因分析

日期：2026年11月16日。依据：11月14日已封存的23轮 gpt-6.1-sol/high Codex app-server 实验、MCP调用证据、原生参数与独立STEP检查。本文单独解释原因；优化后的验证另见《优化说明与验证》。不是生产WebUI/OpenCode全链路验收。

## 二、效率为什么没有提升

五组双方自主完成的匹配任务，Direct合计743.999秒，PTC合计1300.749秒，为1.748倍。主回包减少82.884%，参数加回包减少81.291%，但外层调用110→240、后端派发110→488；低回包量没有抵消额外启动、目录发现、状态轮询和验证往返。

源码确认0.2.0每次catalog及程序都重新启动两套stdio后端、initialize并list_tools。每个短程序也另起QuickJS运行时。Direct基线原本允许一次原生宏或plan完成多步，不是逐特征逐轮调用的弱基线。PTC的理论优势只有在程序真正合并操作、压缩中间结果时才可能体现。

累计provider token遥测为6145211 / 10807527，包含缓存，不等于计费token。每组仅一轮、顺序及模型随机性混杂；不能由这些数据推出通用速度或费用结论。

## 三、草图编辑状态为什么丢失

SketcherTools把_active_sketch和_active_factory放在后端对象内存。R2程序008创建并绘制矩形，009试图关闭；两个程序各自新建后端，不能继承前一个进程的对象句柄。关闭工具尝试接管InWorkObject也未成功，完整错误发生在CloseEdition之前。

改进：同一个PTC服务生命周期保留两套后端与schema；用专属异步任务顺序派发，保证MCP/anyio上下文由同一任务进入退出。建议仍把“开草图—绘图—关闭—切除”写在一个program，并用catia_plan_run取得步骤组原子执行。连接复用不等于跨服务重启恢复草图，也不等于跨调用独占CATIA。

## 四、正确几何为什么自检失败

F1重开前后体积1262949.1850和1262949.1852 mm³，相对差约1.6×10^-10。用固定绝对容差0.0001 mm³对百万量级体积复核，会把正常显示/序列化舍入视为失败。

改进：提供有限数值校验及显式abs/rel容差，输出actual、expected、delta、limit；量纲和工程容差由调用者确定。仅同一CATIA保存/重开数值一致性可采用如abs=0.001 mm³、rel=1e-8。不得用这一例值代替设计公差，更不能靠放宽容差遮盖顶盖/翼子板CATIA与OCP约0.6–0.8%的未解决体积差。

## 五、曲率修改为什么耗时且核验中断

R3原49点、147个XYZ值已按目标公式更新，身份和其他参数不变，独立STEP指定采样通过。但验证过程中做了98次测距；前8异常，后续限定路径名称未找到。上游名称搜索取首匹配，没有唯一性证明；距离代码乘1000且注释承认尚未实机确认。

改进：优先一次读取命名参数，用循环验证49组XYZ和不应变化的参数，再用独立STEP检查材料、厚度和指定曲率采样。未校准距离不能作为验收依据；发现异常应停止该验证路径并明确报告，不继续扩散到98次。此轮不未经实机校准修改测距单位，也不声称修复了所有名称解析。

## 六、为什么工具外层成功仍可能没有识别结果

上游面/边枚举曾返回“Could not enumerate faces/edges: …”，但isError=false、plan为SUCCEEDED。0.2.0封装主要识别Error/Failed/Exception开头，漏掉这些业务失败；嵌套结构化ok=false也可能被外层成功掩盖。

改进：解析实际嵌套业务结果，并对已观察的枚举失败前缀判失败、保留原错误。只改PTC投影，不篡改上游原始记录或共享执行门；传输/RPC不确定仍阻断，不自动重试。空列表、“No faces found”等合法空结果不能误判失败。

## 七、截图为什么没有自动纠错

主实验只返回截图路径，没有向模型发送实际图片像素，因此不能称为视觉自检。WFB辅助纠错确实给了1张绑定图片和Hub103/目标100的明确测量，仅修改Hub并通过指定检查；这是辅助已知故障，不是盲图理解或自发修复。

已有include_feedback=true能返回绑定任务截图的MCP ImageContent，但模型仍需主动读取并结合原始目标、数值读回决定修正。不能把截图存在等同于视觉闭环；未知写操作不能靠图像猜测结束后继续执行。

## 八、修复优先级与验收边界

1. P0：服务内连接/草图句柄复用；真实CATIA跨程序草图回归及错误终态测试。
2. P0：嵌套业务失败准确反馈；QuickJS回归验证失败后不继续派发。
3. P1：显式abs/rel数值辅助函数；舍入误差通过、真实偏差拒绝。
4. P1：执行入口可等待最多20秒、目录缓存和合并操作工作流；只读冷/热连接对照计时。
5. 待专项验证：测距单位、名称唯一绑定、阵列几何失败根因、复杂曲面体积差、真正多轮视觉纠错。

旧测试、旧失败及其封存包保持不变。新的机制回归与固定脚本计时，不能替代8项自然语言任务完整重测，也不构成A级曲面/G1/G2/制造认证。
